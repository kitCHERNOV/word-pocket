# План переноса дизайна WordPocket в Android-приложение

## 1. Цель и результаты анализа

Перенести визуальный стиль `design/index.html` и `design/README.md` в нативный интерфейс Jetpack Compose: бумажные поверхности, терракотовые акценты, книжную типографику и спокойную композицию экранов.

Проект состоит из одного Android-модуля. Room хранит словари, карточки и очередь изучения; репозиторий выполняет операции с данными; ViewModel управляет занятиями; Compose отображает экраны. Основная функциональность прототипа уже реализована. Перенос требует переработки оформления и компоновки, а также изменения обработки правильного выбора.

Согласованные требования:

- Сохранить светлую и системную тёмную темы.
- После правильного выбора из четырёх вариантов сразу показывать следующую карточку — в изучении и повторении.
- После письменного ответа, ошибки или «Пока не знаю» оставлять разбор и кнопку продолжения.
- Сохранить существующие данные, правила обучения и совместимость JSON.

## 2. Дизайн-система и оформление Android

Основные изменения сосредоточить в `ui/Theme.kt` и `ui/Screens.kt`. Выделить общие компоненты оформления и отдельные компоненты экранов, чтобы не увеличивать существующий монолитный файл.

### Цвета и типографика

Светлую палитру перенести из CSS прототипа:

| Назначение | Цвет |
|---|---|
| Бумажный фон | `#F8F6F1` |
| Поверхность карточек | `#FFFEFA` |
| Основной текст | `#30312B` |
| Вторичный текст | `#777970` |
| Разделители | `#E6E3DA` |
| Терракотовый акцент | `#C36B4F` |
| Подложка блока обучения | `#F2E7DC` |
| Прогресс словаря | `#929B7A` |

Для правильного ответа использовать `#537052` / `#EDF2E8`, для ошибки — `#A54439` / `#FAEEE9`.

Тёмную тему построить на тёплых оттенках: фон `#211F1B`, поверхности `#2B2823`, текст `#EEE9DF`, вторичный текст `#B8B1A5`, разделители `#484238`, акцент `#DF987C`. Цвета состояний адаптировать с проверкой контраста.

Использовать системный `FontFamily.Serif` для бренда, крупных заголовков, слов и числовых показателей; `SansSerif` — для подписей и управления. Сторонние шрифты и сетевые загрузки не добавлять.

### Общие компоненты

- Боковые отступы телефона — 22 dp; скругления — преимущественно 10–18 dp; минимальные тени и тонкие границы.
- Области нажатия — от 48 dp, включая визуально небольшие иконки.
- Перенести линейные иконки прототипа в локальные векторные ресурсы.
- Унифицировать основные, вторичные и опасные кнопки, поля, фильтры, индикаторы серии и диалоги.
- Согласовать системные панели, фон запуска и цвет существующей иконки приложения с новой палитрой.
- Сохранить edge-to-edge и корректные отступы под системные панели и клавиатуру.

## 3. Перенос экранов

### Библиотека

Повторить композицию прототипа: бренд с символом солнца, вводный блок «Слова остаются с вами», статистика с разделителями, заголовок «Ваши словари», карточки словарей с книжными иконками и тонким прогрессом.

Добавить нижний информационный блок с листком. Кнопку «Новый словарь» закрепить в нижней панели; создание также доступно через плюс в шапке. Статистику показывать и при нулевых значениях.

### Словарь

Перенести крупное название, подпись «Личная коллекция», статистику и тонированный блок занятия. Повторение разместить внутри блока, основную кнопку изучения — в нижней панели.

Настройки открыть иконкой в шапке. Добавление карточки разместить рядом с заголовком списка; импорт и экспорт — отдельной строкой.

Заменить отдельные объёмные карточки слов компактными строками с разделителями: английский текст, необязательная транскрипция, перевод и статус либо точки серии. Сохранить поиск, фильтры, редактирование и все пустые состояния.

### Занятие и результат

Перенести тонкий прогресс, сегментированный переключатель формата, центральную карточку вопроса, сетку ответов 2×2, письменное поле и действие «Пока не знаю».

При ручном разборе показывать ответ и транскрипцию. Для ошибочного выбора подсвечивать выбранный неверный и правильный варианты; блокировать повторный ответ. Кнопку «Продолжить» размещать в нижней панели.

Экран завершения оформить символом солнца, книжным заголовком, итоговым количеством карточек и кнопкой возврата в словарь.

### Формы и адаптация

Оформить создание, настройки, редактирование, подтверждения удаления и выхода в стиле прототипа. Сохранить ограничения полей и предупреждения о сбросе прогресса. В форме нового словаря сделать размер пула доступным сразу; значение по умолчанию оставить **10**, диапазон — **1–100**.

На широких экранах ограничить контент 720 dp, занятие — 470 dp; при ширине от 600 dp показывать словари двумя колонками. На телефонах использовать одну колонку. Длинные тексты и увеличенный системный шрифт должны переноситься без обрезки действий.

## 4. Автопереход и интерфейсы состояния

Изменения внести в `ui/AppViewModel.kt`; решение о переходе принимать во ViewModel.

- Добавить в состояние занятия уникальный номер показа `questionToken`. Увеличивать его при каждом новом вопросе, включая повторный показ того же слова.
- Передавать с ответом токен и фактический формат ответа. Автоматический письменный режим при недостатке вариантов должен считаться письменным.
- Принимать ответ только для актуального токена, при отсутствии уже принятого ответа и выполняющейся операции.
- Сначала сохранить результат существующей транзакцией либо обновить очередь повторения.
- При верном выборе сразу загрузить следующий вопрос, без таймера, промежуточного разбора и кнопки продолжения. Если очередь завершена, сразу показать итог.
- Для остальных ответов сохранить ручной разбор. Добавить выбранный ответ в `Feedback` для подсветки вариантов.
- Привязать очистку ввода и состояние показа карточки к токену, а не только к ID слова. Защитить ручное продолжение от устаревших событий аналогично.
- При ошибке сохранения оставить текущий вопрос и вывести сообщение. Если ответ уже сохранён, но загрузка следующего вопроса завершилась ошибкой, разрешать повтор загрузки без повторного зачёта ответа.

Room-схему и JSON не менять. Сохранить три правильных ответа подряд, фиксированный пул, нормализацию ответов и неизменность статуса выученного слова при ошибке в повторении.

## 5. Проверка и критерии готовности

### Автоматические проверки

Сохранить существующие 12 JVM-тестов. Добавить инструментальные тесты ViewModel и Compose с временной Room-базой; предусмотреть передачу тестового репозитория в ViewModel при сохранении штатного создания приложения.

Проверить:

- Верный выбор в изучении и повторении переводит к следующему вопросу без кнопки.
- Третий верный ответ выводит слово из пула; последний ответ открывает итог.
- Пул из одного слова корректно обновляет номер показа и серию.
- Письменный ответ, ошибка и «Пока не знаю» оставляют разбор.
- Повторное событие со старым токеном не меняет следующую карточку.
- Недостаток вариантов включает письменный режим.
- Ошибка сохранения не продвигает занятие.

Запустить:

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
.\gradlew.bat connectedDebugAndroidTest
```

Последняя команда требует устройства или эмулятора. При отсутствии устройства дополнительно запускать общие сценарии Compose/Room через Robolectric на JVM; такой запуск не заменяет приёмку на Android-устройстве.

### Ручная приёмка

Сравнить основные экраны со светлым прототипом на одинаковых данных. Проверить тёмную тему, маленький экран, крупный шрифт, поворот, клавиатуру и системный жест назад.

Пройти существующие сценарии приёмки: импорт/экспорт, изоляция словарей, сохранение пула после перезапуска и работа офлайн. Проверить обновление установленного приложения с сохранением базы и прежней подписью.

Обновить README и документ ручной приёмки, приложить сравнительные скриншоты. Невыполненные проверки отметить явно.

Демонстрационную рамку телефона, фиктивную строку состояния, браузерные настройки ширины, сброс демо и предзаполненные словари в приложение не переносить. Сам HTML-прототип оставить исходным визуальным эталоном.
